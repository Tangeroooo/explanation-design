# 독립 다이어그램 평가 절차 시험

2026-11-25, 기존 `main`의 `a839340` 예제로 두 단계 평가를 실제 실행했다. 새 테마로 그림을 제작하거나 평가자 유무의 성능을 비교한 실험은 아니다.

## 입력과 독립성

- 별도 agent 하나를 제작 대화 이력 없이 시작했다. 원본 변경·게시·추가 agent 생성은 허용하지 않았다.
- 1단계에는 [실제 PNG](../examples/code/figures/delivery-flow.png), 표시 크기 1280×721 px, async 호출을 이해하는 엔지니어라는 독자 정보, “deliver가 실패했을 때 어디까지 실행되었는가?”라는 질문만 전달했다. 문서 본문을 동반하지 않은 단독 그림 평가다.
- 이미지 열람 후 [첫 해석](independent/diagram-first-reading.md)을 회수하고 SHA256 `8c15607e01c33c93122559f52f17f579abc39d72120d8d810d98f1f0f098ace8`로 고정했다. 근거 대조 후에도 원본 기록의 hash가 같았다.
- 이후 같은 agent에게 [원본 코드](../examples/code/input/worker.py), [기존 명세](../examples/code/figures/brief.md), 현재 테마와 평가 절차를 전달했다. 과거 명세와 새 그림용 테마는 구분하도록 했다. 제작자의 자기평가·과거 평가 결과·정답지는 전달하지 않았다.
- agent는 PNG를 다시 열고 입력 hash를 확인해 [근거 대조 결과](independent/diagram-evidence-review.md)를 반환했다. 결과 파일을 저장소에 보존할 때 임시·절대 파일 경로만 상대 경로로 바꿨다. 위 첫 해석 hash는 경로 정규화 전 원본의 hash다.

| 입력 | SHA256 |
|---|---|
| PNG | `3fb4e3d0e7a7de53b1436e8ccf3d6a6ae53ebc80f80972970b99cf081dcf4025` |
| worker.py | `347797feff39c532dbc7692a8f5ec147c28ed305c8f0ed685d5df595a6c2402e` |
| 기존 brief | `096cfc9a421ee46c55a558abb6c6290d9e3ec5a11552f714774f4c3fd79357ec` |

## 관측과 지적 처리

첫 해석은 send 예외 시 ack 미호출, ack 예외 시 send 정상 반환, 두 경우 모두 외부 효과 미확인을 구분했다. 이후 코드를 읽고 이 해석이 근거와 일치한다고 판단했다. 폰트 이름은 이미지에서 추측해 확정하지 않았고, 핵심 흐름의 의미적 일치를 전체 시각 검증 통과로 확대하지 않았다.

주 agent도 PNG와 코드를 열어 다음과 같이 판단했다. 원시 평가 결과는 수정하지 않고 이 처리 기록과 함께 보존한다.

| 지적 | 처리 | 이유와 남은 조치 |
|---|---|---|
| R1: 작은 보조 라벨 | 개선 후보로 수용, 차단 결함으로는 판단하지 않음 | 핵심 경로는 읽힌다. 실제 글자 크기·대비 측정과 새 렌더가 없으므로 개선 완료는 아니다. |
| R2: 두 예외 상자의 다른 색이 현재 테마 위반 | 확정 위반이라는 해석은 수용하지 않음 | 당시 명세는 한 곳의 강조를 지정했다. 역할 식별·상태·강조는 다른 축이며, 예외 결과라는 이유만으로 항상 같은 색이어야 한다는 규칙은 없다. 현재 토큰의 정확한 불일치도 측정하지 않았다. 과거 그림을 새 테마 준수의 증거로 쓰지 않는다는 한계는 유지한다. |
| R3: 실제 Noto Sans KR 사용 미검증 | 수용, 미검증 유지 | PNG와 CSS 이름만으로 실제 렌더 폰트를 입증할 수 없다. 이번 시험에는 폰트 관측이나 재export가 없다. |
| R4: durability 대상 명료화 | 선택적 제안으로 수용 | 의미 오류나 필수 수정은 아니다. 해당 대상의 계약이 없으므로 표현을 구체화하면서 새로운 보장을 만들면 안 된다. |

R2를 검토하며 평가 지침을 좁게 보완했다. 스타일은 해당 산출물의 명세·명시적 변경을 기준으로 판단하고, 역할·상태·강조를 먼저 구분하도록 했다. 수정된 지침으로 독립 재실행하지는 않았다. 평가자의 지적도 근거로 판단해야 한다는 실제 사례이며, 모든 지적을 자동 수정 요구로 삼지 않는다.

## 범위와 한계

- 관측한 평가 비용은 agent 하나의 두 차례 실행이다. 토큰·시간 비용과 작성자 자체 검토 대비 추가 발견 수는 측정하지 않았다.
- 기존 그림은 역사적 예제로 유지했다. 재생성·수정 라운드는 **0회**이며, 수정 후 회귀 탐지·최대 두 차례 종료·그림 묶음 간 일관성은 이번 시험에서 실행하지 않았다.
- 이 시험은 실제 이미지 해석, 근거의 단계적 공개, 미확인 유지, 지적의 수용·반박 처리를 확인한다. 새 테마 제작, 자동 skill 선택, 도구가 없는 환경의 대체 동작, 다른 agent 환경, 실제 독자 이해도 향상은 검증하지 않았다.
- 기존 그림의 호출 의미는 일치하지만 현재 테마·실제 폰트까지 통과했다고 주장하지 않는다. 새로운 의미 오류를 발견했다거나 평가 agent 도입의 일반적인 품질 향상이 입증됐다고 주장하지 않는다.
