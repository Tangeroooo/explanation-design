# 그림 제작 명세 — 컴포넌트 전달 시험

- ID: component-handoff. 제목: 프로세스별 소유 범위와 worker 추가.
- 독자: 시스템 구조를 이해하려는 엔지니어.
- 질문: 책임·접점·자원은 어디에 속하며, P에 worker 하나를 추가하면 무엇이 달라지는가?
- 메시지: mailbox는 worker별로, pool은 프로세스별로 존재한다. P의 추가 worker는 자신의 mailbox와 기존 P pool을 사용하며 Q는 그대로다.
- 근거: S1 = input.md, 2026-11-26의 가상 시스템 명세. 아래 S1.n은 항목 번호다. 명시된 사실이며 실제 운영 시스템 관측이 아니다.
- 유형: 컴포넌트 구조도. 논리 서비스와 프로세스 관점 전환을 표시한다. 실행 순서 그림이 아니다.
- 표현: 아래 컴포넌트 명세를 사용한다. C1/C2 등은 명세 ID이고 독자용 라벨을 대체하지 않는다.
- 출력: diagram-design의 HTML/SVG, 표시 크기 2배 PNG. 1280 CSS px 폭에서 읽히게 설계하며 높이는 제작자가 결정한다. 제목 30px/700, 주요 선 2.5px, 주요 경계 2px, 제안 3px. 도형 이름에 관계 의미를 싣는다.
- 스타일: explanation-design의 고정 밝은 역할 팔레트. 설명 Noto Sans KR, 정확한 코드·식별자는 고정폭. 테마 선택·프로필 저장 질문이나 승인 대기 없음. 구조를 보존하며 배치·간격·좌표는 자유롭게 결정한다.
- 생략: Catalog의 내부와 helper/key 매핑은 이번 질문 범위 밖이다. Catalog 배포·내구성은 미상이다. 처리량·병렬 실행·메일 수신 순서는 주장하지 않는다.
- 의미 수용 기준: 아래 경계·개수·공유·접점과 제안 범위를 보존하며 미상 계약을 추가하지 않는다.
- 시각 수용 기준: 실제 표시 폭에서 이름·접점·선 끝점·내부 구획을 판독할 수 있고 겹침·잘림이 없어야 한다. PNG 배율과 표시 크기를 구분한다.

## 범위와 계층

S는 논리 서비스이고 P/Q는 그 배포 프로세스다(S1.1). S를 세 번째 프로세스로 그리지 않는다. P는 변경을 설명하기 위해 펼치고 Q는 같은 구성의 수량을 요약한다. 다음은 소유 관계이며 실행 순서가 아니다.

```text
S (논리 서비스; 배포 대응 → P, Q)
  P (프로세스)
    P.coordinator ×1
    P.worker[i] ×3 현재 / ×4 제안
      P.mailbox[i] ×1 per worker
    P.pool ×1, P.worker[i]가 공유
  Q (프로세스; 현재=제안)
    Q.coordinator ×1
    Q.worker[i] ×3
      Q.mailbox[i] ×1 per worker
    Q.pool ×1, Q.worker[i]가 공유
Catalog (논리 외부 대상; 배포 위치 미상)
```

## 관계

- R1: C4 → 선택된 C6.`enqueue(job)`: job 전달(사실 S1.3). C4의 외부 입력 접점은 `submit(job)`이고 이 출력과 혼동하지 않는다. 송신 API는 미상이라 출발 끝점은 C4 컴포넌트다. 현재 worker 셋 중 하나의 mailbox로 가는 대표 연결을 그리고 `선택된 mailbox 하나로 전달 · 선택 규칙 미상`으로 설명한다. 특정 worker 고정, broadcast, round-robin을 뜻하지 않는다.
- R2: 각 C5 — C7: 자원 공유(사실 S1.2), 무방향. 처리 순서·잠금·pool API를 뜻하지 않는다. 제안 worker도 동일 C7에 연결(S1.4).
- R3: C1 → C9: 논리 record 갱신 요약(사실 S1.1). 개별 worker나 coordinator에서 호출한다고 좁히지 않는다.
- 소속은 위 계층과 포함 경계로 표현하며 별도 화살표를 반복하지 않는다. mailbox→worker 소비 경로는 미상이므로 그리지 않는다.

## 변경·제작 전 점검

- 추가 worker와 그 mailbox만 제안으로 점선/문구 표시한다. 기존 P.pool과 Q에는 변경 표시를 붙이지 않는다(S1.4).
- P.worker[1]은 자기 mailbox를 소유하고 P.pool을 공유한다(S1.2). 이 인스턴스의 경계를 따라 추적해도 pool이 worker 안으로 들어가면 안 된다.
- R1의 대상 접점은 worker 본체가 아니라 그 mailbox의 `enqueue(job)`다(S1.3). 어떤 worker를 고르는지는 미상이다.
- 미상 API·용량·선택 규칙·소비 순서는 명세 작성 누락이 아니라 근거 부족이다. 도형이나 선으로 채우지 않는다.
- 남은 제작 판단은 좌표·높이·선 경로·요약 구획 배치다. 위 의미를 바꿔야 할 상황이면 추가 시스템 사실을 추측하지 말고 부족한 명세를 보고한다.
