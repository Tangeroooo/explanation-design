# 독립 다이어그램 평가 — 근거 대조

## 결론과 적용 범위

그림의 핵심 실행 의미는 제공된 코드와 일치한다. send에서 예외가 나면 ack는 호출되지 않고, ack에서 예외가 나면 send는 이미 정상 반환했다. 외부 부수 효과·영속성·broker 상태를 UNKNOWN으로 남긴 것도 코드의 근거 범위에 맞는다. 의미 오류는 발견하지 않았다.

다만 보조 글씨 가독성에는 개선 여지가 있고, 기존 그림의 실패 역할 색상은 현재 새 산출물용 테마 규칙과 일치하지 않는다. 실제 폰트와 접근성·출력 동작은 미검증이다. 따라서 모든 항목을 포괄하는 최종 통과로 표시하지 않는다. 현재 테마는 새 그림에 대한 요구이며, 이를 과거 제작 명세의 소급 위반으로 판정하지 않는다.

이 기록은 초기 독립 평가의 2단계이다. 첫 해석은 보존했고 수정하지 않았다. 수정·재평가 라운드는 0회이며, 제작자의 지적 수용·거절 결정은 아직 받지 않았다.

## 검사한 대상과 도구 관측

- 실제 PNG: `../../examples/code/figures/delivery-flow.png`. `view_image`로 첫 단계 및 근거 대조 단계에 열었다. 의도한 표시 크기와 원본은 제공된 1280×721 px를 기준으로 했다.
- 원시 코드: `../../examples/code/input/worker.py` 전체. 실행하지 않고 읽었다.
- 기존 제작 명세: `../../examples/code/figures/brief.md` 전체. 연결된 다른 파일은 읽지 않았다.
- 평가 절차: `../../skills/explanation-design/references/verification.md`의 Independent diagram review 절.
- 현재 테마: `../../skills/explanation-design/references/diagram-theme.md`.
- 첫 해석: 앞 단계에서 직접 작성한 `diagram-first-reading.md`의 해석과 대조했다.
- `sha256sum` 결과는 전달받은 값과 모두 일치했다. 이 검사는 입력의 동일성만 확인하며 그림의 의미나 폰트를 검증하지 않는다.

기존 main `a839340`과 동일한 예제라는 정보는 전달받은 버전 맥락이다. git 이력을 별도로 조사하지 않았다. 브라우저의 실제 rendered-font 관측, 자동 기하 검사, HTML/SVG 접근성 검사, export 재생성은 수행하지 않았다.

## 첫 해석과 근거의 대조

| 그림에서 읽힌 의미 | 코드·명세 근거 | 결과 |
|---|---|---|
| deliver → send → ack → 문자열 반환 순서 | `worker.py:20–23`에 순차적인 두 await와 return이 있다. | 일치 |
| send가 예외를 내면 ack 미호출, 예외 전파 | send await 다음에 ack가 있고 예외를 잡는 코드가 없다. | 일치 |
| ack가 예외를 내면 send는 정상 반환했고 마지막 return에는 미도달 | ack await는 send 다음이며 return 이전이다. | 일치 |
| 정상 반환과 외부 영속성은 별개이며 외부 상태는 UNKNOWN | `Sink`·`Broker`는 구현 없는 Protocol이며 외부 정책이 미지정이라고 명시되어 있다. | UNKNOWN 유지가 적절함 |
| 소유권·프로세스 경계는 알 수 없음 | 제공된 코드에는 호출 대상 인터페이스만 있다. | 경계를 그리지 않은 것이 근거 범위에 맞음 |
| 재시도·재배달·취소·crash 동작은 알 수 없음 | 명세가 이를 범위 밖으로 두며 외부 계약도 없다. | 이 그림에서 생략한 것을 오류로 보지 않음 |

구체적인 조건 변화도 대조했다. send 예외를 ack 예외로 옮기면, ack의 실행 여부는 ‘미호출’에서 ‘호출됨’으로 바뀌고 send의 결과는 ‘예외’에서 ‘정상 반환’으로 바뀐다. 두 경우 모두 외부 효과의 확정 여부는 UNKNOWN으로 남는다. 그림은 이 차이와 공통 한계를 유지한다.

## 표현 방식·도형·경계

flowchart는 이 질문에 적절하다. 두 await가 별도 처리 상자이고, 위에서 아래로 이어지는 정상 경로와 옆으로 빠지는 예외 경로가 질문에 직접 대응한다. 6개 노드·5개 연결은 명세의 요소와 일치한다. 별도 판단 다이아몬드가 없어도 RETURNS와 RAISES 라벨로 분기가 구별된다.

시작·정상 종료·예외 결과를 둥근 도형으로, await 처리를 사각 도형으로 구분한 것은 읽는 데 방해되지 않는다. 컨테이너나 swimlane이 없어 근거 없는 소유권·실행 위치를 암시하지 않는다. 이 단일 그림에는 별도 overview/detail 쌍이 없으므로 그 사이 대응은 적용 대상이 아니다. 연결된 문서나 다른 그림과의 일치 여부는 검사하지 않았다.

## 지적

아래 모든 지적의 대상 버전은 위 SHA256의 PNG이다. ‘현재 테마 기준’과 ‘기존 명세 기준’을 구분한다.

| ID | 시각 위치 | 분류 | 독자가 읽는 의미 | 근거 또는 부족한 근거 | 영향 | 최소 수정 |
|---|---|---|---|---|---|---|
| R1 | 두 실패 상자 아래의 UNKNOWN 설명, RETURNS/RAISES, 코드 위치, 하단 주석 | readability defect | 큰 호출 이름을 먼저 읽고 외부 상태의 불확실성 및 분기 조건은 늦게 확인하거나 놓칠 수 있다. | 실제 1280×721 이미지에서 보조 글씨가 본문보다 상당히 작다. 다만 이번 관찰에서 판독은 가능했으며, 정확한 글자 크기와 명암비는 측정하지 않았다. | 경미한 가독성 문제. 필수 내용이 판독 불가능하다고 판정할 근거는 없다. | 특히 UNKNOWN 설명과 분기 라벨의 글자 크기를 높이고 원본 표시 크기에서 다시 확인한다. |
| R2 | 왼쪽 send 예외 상자는 중립색, 오른쪽 ack 예외 상자는 주황색 강조 | requirement mismatch — 현재 새 산출물 테마 기준 | 같은 실패 결과인데 서로 다른 역할 또는 위험도를 가진 것으로 읽힐 수 있다. | 현재 테마는 역할 색상 일관성과 Failure/danger 색상을 요구하며, 강조 노드 수를 맞추기 위해 역할 전체를 다시 칠하지 않도록 한다. 기존 명세는 당시 기본 light와 focal node 1개를 요구했다. 따라서 과거 명세의 위반이라고 단정하지 않는다. 이미지에서는 두 실패 역할의 서로 다른 처리 자체가 확인된다. | 기존 실행 의미를 깨뜨리지는 않는다. 현재 테마를 만족하는 새 그림이라고 주장할 때는 미충족 요건이다. 정확한 색상 token 값은 측정하지 않았다. | 현재 테마로 재사용할 경우 두 예외 상자에 같은 failure 역할 색상을 쓰고, 오른쪽 강조가 필요하면 선 굵기 등으로 분리한다. 과거 그림 평가만 수행하는 이번 작업에서는 원본을 바꾸지 않는다. |
| R3 | 전체 텍스트, 특히 보조 영문 라벨·하단 주석 | unverified claim | Noto Sans KR 사용 또는 한글·영문 전체의 지정 폰트 적용이 확인됐다고 볼 수 없다. | 현재 테마는 모든 가시 텍스트의 실제 Noto Sans KR 렌더링을 요구한다. 기존 명세의 web font와 offline fallback 허용 기록은 실제 폰트 관측이 아니다. PNG만으로 정확한 family를 확정할 수 없다. | 폰트 검증은 미완료다. 실제로 다른 폰트라고 확정하거나 해당 검사를 통과시킬 수 없다. | 실제 export 환경에서 폰트 로딩 완료와 모든 텍스트 역할의 rendered font를 관측하고 기록한다. 필요하다면 그 뒤 같은 폰트로 측정·재생성한다. |
| R4 | 오른쪽 실패 상자 하단의 `durability / broker state: UNKNOWN` | optional preference | 무엇의 durability인지 특정하지 못할 수 있다. | 첫 해석에서 대상이 모호했다. 코드에는 sink 저장·broker 반영의 구체 계약이 없고, 명세는 외부 내구성을 별도 계약으로만 둔다. UNKNOWN 자체는 정확하다. | 실행 순서 질문의 답에는 지장이 적다. 의미 오류로 분류하지 않는다. | `외부 효과·영속성·broker 상태: 미확인`처럼 코드가 보장하지 않는 범위를 더 명시하거나, 확인하려는 내구성 대상이 정해지면 그 대상을 적는다. |

R2는 현재 테마 적합성 판단에 한정된 지적이다. R3은 증거 부족이며, 폰트 불일치 확정 지적이 아니다. R4는 선택적 명료화 제안으로 통과를 막는 결함이 아니다. quota를 채우기 위한 의미 오류나 미측정 수치 결함은 추가하지 않았다.

## 결과와 남은 한계

| 검토 축 | 결과 | 판단 한계 |
|---|---|---|
| 의미적 일치 | 지정된 코드와 명세의 핵심 실행 순서·실패 결과에 일치 | 실제 외부 구현·계약은 없으므로 실행 결과나 영속성을 보장하지 않음 |
| 원본 크기 가독성 | 핵심 노드·화살표·분기를 읽을 수 있고 눈에 띄는 잘림·겹침은 관찰되지 않음. R1 개선 권고 | 자동 기하·글자 크기·명암비 검사 및 좁은 화면 테스트는 없음 |
| 기존 제작 명세 | 노드·연결·실패 경로·UNKNOWN 표현·직선 연결은 일치 | 한국어 12px 이상, 접근 가능한 title/desc, local scroll, print, 다른 형식과의 일치는 PNG만으로 확인 불가 |
| 현재 테마 | 역할 색상 적용은 R2의 불일치가 있음 | 새 그림용 규칙과 과거 제작 기록을 구분함. 정확한 색상 수치와 모든 token의 적합성은 미측정 |
| 실제 폰트 | 미검증 | Noto Sans KR 적용·로드 완료·export 전 측정 모두 확인 자료 없음 |
| 근거 연결 | 코드 파일과 이미지의 행 번호는 맞음 | `C1–C4`와 `S1`의 전체 문서 매핑은 제공된 명세의 설명 범위를 넘어 확인하지 않음 |
| 입력 동일성 | 전달받은 세 파일의 SHA256과 일치 | 생성 소스와 PNG의 재생성 일치나 main 커밋 자체를 검증한 것은 아님 |
| 독자 이해도 | 독립 평가자의 첫 해석이 코드와 일치 | 실제 독자 대상 실험이나 이해도 향상 증거는 아님 |

기존 명세는 1280×720을 적고 있고 전달된 이미지는 1280×721이다. 이번 의도한 표시 크기는 1280×721로 명시되어 있어 크기 결함으로 제기하지 않는다.

이번 단계에서 제작자의 사전 판단, 과거 평가 결과, 정답지와 연결된 파일은 열지 않았다. 따라서 제작자가 이미 찾은 결함을 넘어 새 결함을 발견했다거나 평가 품질이 개선됐다고 주장할 근거는 없다. 제작자가 지적을 수용·거절하고 수정본을 전달하면 해당 지적 및 변경 영향 범위만 재평가하면 된다.

원본 수정·재export·게시와 실제 폰트/브라우저 검증은 수행하지 않았다. 실행 의미의 일치를 전체 시각·폰트·현재 테마 검증 통과로 확대해서는 안 된다.
