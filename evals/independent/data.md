# B의 전체 오류율은 높지만, 집단별 관측 오류율은 낮다

이 데이터만으로 “B가 더 좋아졌다”는 단일 결론을 내릴 수 없습니다. 전체 요청 기준 오류율은 A 1.9%에서 B 7.2%로 높아졌습니다. 반면 light와 heavy 각각에서는 B의 관측 오류율이 낮습니다. B에 오류율이 높은 heavy 요청이 훨씬 많이 포함되어 있어 전체와 집단별 방향이 다릅니다. 무작위 배정 자료가 아니므로 B 자체의 인과 효과는 확정하지 않습니다.

## 원본과 계산 범위

자료는 설명용 **합성 데이터**입니다. [cohorts.csv](../../examples/data/input/cohorts.csv)의 각 row는 variant·cohort별 요청 수와 오류 수이며, [context.md](../../examples/data/input/context.md)에 따르면 같은 설명용 기간의 합계입니다. 요청이 관측 단위이며 사용자 중복 여부와 무작위 배정은 제공되지 않았습니다.

`오류율 = errors / requests`로 계산했습니다. 전체는 cohort 오류율의 단순 평균이 아니라 **오류 수 합계 / 요청 수 합계**입니다. 원본 4행에 결측·0 denominator·중복 variant/cohort row는 없으며, 0 errors는 유효한 관측으로 유지했습니다.

## 계산 결과

| 범위 | A 오류 / 요청 | A 오류율 | B 오류 / 요청 | B 오류율 | B−A | A 대비 상대 변화 |
|---|---:|---:|---:|---:|---:|---:|
| 전체 | 19 / 1,000 | 1.9% | 72 / 1,000 | 7.2% | +5.3 percentage points | 약 +278.95% |
| light | 9 / 900 | 1.0% | 0 / 100 | 0.0% | −1.0 percentage point | −100% |
| heavy | 10 / 100 | 10.0% | 72 / 900 | 8.0% | −2.0 percentage points | −20% |

전체 오류 수는 같은 총 요청 수 1,000건에서 19건→72건으로 **53건 증가**했습니다. 오류율의 절대 차이는 `7.2% − 1.9% = 5.3 percentage points`이며, 상대 변화는 `(7.2 − 1.9) / 1.9 × 100 ≈ 278.95%`입니다. B의 전체 오류율은 A의 약 3.789배입니다. “5.3% 증가”라고만 쓰면 percentage point와 상대 변화가 혼동됩니다.

## 왜 방향이 뒤집히는가

| 요청 구성 | A | B |
|---|---:|---:|
| light 비중 | 90% | 10% |
| heavy 비중 | 10% | 90% |

전체 오류율은 집단별 오류율을 요청 비중으로 가중한 값입니다.

```text
A = 0.9 × 1% + 0.1 × 10% = 1.9%
B = 0.1 × 0% + 0.9 ×  8% = 7.2%
```

각 집단의 B 관측 오류율은 낮아도, B는 heavy 요청의 비중이 90%여서 전체 오류율이 높습니다. 따라서 전체 7.2%만으로 “각 workload에서 B가 나쁘다”고 해석하면 틀립니다. 반대로 집단별 감소만으로 실제 전체 운영 오류가 줄었다고 말해도 틀립니다.

비교 보조용으로 A의 요청 비중을 두 variant에 동일하게 적용하면, B의 표준화 오류율은 `0.9 × 0% + 0.1 × 8% = 0.8%`입니다. A 1.9%와의 차이는 −1.1 percentage points입니다. 이는 **A 구성에서 관측 집단별 비율을 재가중한 계산**이지, 실제 관측된 B 전체 오류율이나 인과 효과가 아닙니다. 다른 workload 비중을 적용하면 결과도 달라집니다.

## 무엇을 결론낼 수 있는가

- **관측 사실**: 실제 제공된 mix의 전체 오류율은 B가 높고, 각 cohort의 관측 오류율은 B가 낮습니다.
- **계산에 따른 해석**: 요청 mix가 달라 전체와 cohort별 방향이 뒤집힙니다. 단순 평균은 이 차이를 숨깁니다.
- **미확인**: B가 오류를 줄인 원인인지, 차이가 우연 변동 범위를 벗어나는지, cohort 안의 요청 난이도가 같은지, 요청 간 독립성이 있는지 확인되지 않았습니다.
- **주의 조건**: B light의 0/100은 이 표본에서 오류가 0건이라는 뜻입니다. 앞으로도 오류율이 0이라는 보장이 아닙니다. A heavy도 100건이라 표본 불균형과 불확실성을 함께 고려해야 합니다.

## 검증과 다음 행동

Python `csv`와 `Decimal`로 원본에서 재계산했고 전체 A 1.9%, B 7.2%와 차이·비중을 확인했습니다. 코드와 계산 결과는 [run_observations.py](run_observations.py), [observations.json](observations.json)에 있습니다. 모든 입력의 SHA-256을 기록했습니다. 통계적 유의성 검정이나 uncertainty interval은 수행하지 않았습니다.

- **단기**: 전체와 cohort별 rate·요청 비중을 함께 보고하고 단일 개선/악화 표현을 피합니다. 비교에 사용할 목표 workload mix를 명시합니다.
- **중기**: 무작위 배정 또는 비교 조건 통제, 사용자·시간·난이도 정보, 표본과 독립성 가정을 확보해 불확실성을 분석합니다.
- **장기**: 실제 운영 목표에 맞는 workload 표준화와 오류율·절대 오류 건수의 동시 관측 기준을 유지합니다.

세 범위의 정확한 비율과 두 집단의 비중을 표로 한눈에 비교할 수 있어 별도 차트는 만들지 않았습니다. 이 결과는 수치·해석 검토이며 production 실험 검증이나 시각 render 검토는 아닙니다.
