# 실제 적용 평가

문구 일치 대신 관측 가능한 판단을 평가한다. cases.json의 criteria는 평가자용이며 독립 실행 agent에 정답으로 주지 않는다.

각 항목: 0 = 누락·오류, 1 = 일부 충족·한계 명시 부족, 2 = 근거와 조건을 포함해 충족. 합계 점수보다 결론을 바꾸는 결함을 우선한다.

- 핵심 질문에 직접 답함.
- 중요한 주장과 출처·버전·조건 연결.
- 인과·실행 순서의 비약 없음.
- 사실/추론/제안/미확인 구별.
- 제약·실패 경로와 선택 전환 조건 포함.
- 표현이 이해를 도우며 과잉 제작 없음.
- 본문·표·그림의 의미 일치.
- 독자가 결론과 한계를 설명할 수 있음.
- 독자의 목표가 추적·비교·예측·판단 중 구체적인 작업으로 정해져 있음.
- 조건 하나를 바꾼 질문에 설명의 규칙으로 답할 수 있고, 결과 유지·변경·미확인을 근거에 맞게 구분함.
- 개요 요소·edge와 상세 그림의 대응을 보존하고, 집계·생략·관점 전환을 명시함.
- 반례의 가정과 결과를 뒷받침하며, 가능한 효과를 설계자의 의도나 유일한 설계의 증거로 과장하지 않음.

조건 변경 평가는 기준 사례와 바꾼 조건을 남기고, 예상 결과 또는 미확인·출처·수정 사항을 기록한다. 정답을 도출하는 데 설명에 없는 사실을 몰래 보충하지 않는다. 자체 검토·독립 agent 평가·실제 독자 평가는 구분하며, 독립 실행에는 raw input과 request만 전달하고 criteria와 평가 기록은 제공하지 않는다.

구조 검사 결과, 근거·의미 평가, 실제 render 시각 검토는 별도로 기록한다. 실행하지 않은 case는 미실행이다. 합성 fixture는 production 검증이 아니다. 발견한 결함 → 일반적인 수정 → 해당 사례 재확인을 남긴다.

독립 다이어그램 평가 절차를 시험할 때는 실제 렌더를 사용하고 첫 이미지 해석이 근거 전달 전에 보존됐는지 확인한다. 이후 근거를 공개해 의미 오류·가독성 결함·요구사항 불일치·미검증 주장·취향을 구분하고, 지적의 위치·독자 해석·근거·영향·최소 수정과 제작자의 수용·반박·미해결 처리를 확인한다. 수정한 경우 재생성된 그림과 관련 그림을 다시 열어 확인하며, 최초 평가 이후 수정·재평가는 최대 두 차례다. 평가 불가나 미해결 문제가 있어도 통과로 표시하지 않는지 확인한다.

시험 기록에는 유효한 추가 발견·기각한 지적·평가 비용·새 결함을 관측한 범위에서 남긴다. 기존 사례를 평가한 결과와 의도적으로 만든 결함 탐지 시험, 새 테마의 제작 검증, 실제 독자 이해도 향상은 서로 다른 증거다. 한 사례의 평가 성공을 일반적인 품질 향상으로 보고하지 않는다.

구조 요청에서는 컴포넌트·인터페이스·소유 경계·공유 자원이 공간적으로 드러나는지 확인한다. sequence-only로 관계를 생략하는 실패와, 순서만 묻는 요청에도 구조도를 강제하는 과잉 교정을 함께 평가한다. 제목 굵기·실제 표시 선 두께·벡터/PNG 크기·삽입 폭을 각각 확인하며, 픽셀 수가 큰 것만으로 가독성을 통과시키지 않는다.
