# 고정 다이어그램 테마

새 그림은 이 밝은 배경과 역할별 팔레트로 제작한다. 견본 가이드의 연한 채움·색상 외곽선·중립색 배경 구조·그림 간 역할 일관성을 따른다. 테마는 이미 선택되었으므로 온보딩 질문으로 되돌리지 않는다. 이후 사용자가 다른 스타일을 명시적으로 요청하면 그 요청을 우선한다.

## 스타일 질문 없이 진행한다

- 테마 선택, 브랜드 URL·색상 토큰 제공, 기본값 유지, 프로필 불러오기·저장, 스타일 견본 승인을 묻지 않는다. 다이어그램 유형·크기·제작 계획의 확인 답변도 기다리지 않는다. 독자의 질문과 실제 표시 크기에 맞게 선택하고, 결과에 영향을 주는 가정을 알린 뒤 진행한다.
- 이 reference를 선택된 스타일과 상시 진행 지침으로 `diagram-design`에 전달한다. 제작자의 기본 팔레트·설명용 글꼴·스타일 온보딩·프로필 저장 제안·그리기 전 확인 대기를 대체한다. 레이아웃·export·검증 지침은 계속 따른다.
- 현재 산출물이나 작업 전용 템플릿에 토큰을 적용한다. 온보딩 조건을 맞추려고 공유 스킬 설치본이나 전역 프로필을 수정하지 않는다. 발견한 저장 프로필로 이 테마를 조용히 교체하지 않는다.
- 내용·근거·출력 제약의 누락으로 올바른 결과를 만들기 어려울 때만 질문한다. 일상적인 시각 선택을 질문으로 돌리지 않는다.

## 실제 표시 굵기와 해상도

제작 템플릿의 더 얇은 기본값 대신 아래 값을 **실제 표시 크기에서** 적용한다. PNG 픽셀 수나 축소 전 SVG 단위가 아니라 CSS pixel 기준이다.

| 요소 | 기본값 |
|---|---|
| 그림 제목 | 28–32px, 굵기 **700**, 본문 색 |
| 컴포넌트·구역 제목 | 16–18px, 굵기 **700** |
| 주요 관계·연결선 | **2–2.5px** |
| 의미 있는 컴포넌트·소유 경계, 보조 연결선 | **1.5–2px** |
| 집중할 관계·변경 경계 | **3px**, 필요한 곳에만 사용 |
| 의미를 담지 않는 격자·구분선 | 0.75–1px, 관계를 전달하는 유일한 수단으로 사용 금지 |

굵어진 선에 맞춰 화살촉·점선 간격·접점·라벨 여백도 조정한다. 불확실성을 표현하려고 중요한 선을 거의 보이지 않게 만들지 않는다. 읽을 수 있는 굵기의 점선과 라벨을 쓴다. 모든 선을 똑같이 굵게 만들지 않고 역할 색과 위계를 유지한다.

비율을 유지해 표시하고 non-scaling stroke를 쓰지 않는 SVG에서는 `표시 선 두께 = 원본 선 두께 × 표시 폭 / viewBox 폭`이다. 글자에도 같은 축소 비율을 고려한다. 의도한 CSS 크기로 설계하는 것을 우선하고, 삽입 화면이 더 작으면 원본이나 배치를 조정한 뒤 다시 확인한다. viewBox가 크거나 PNG가 선명해도 축소 후 얇은 선·작은 글자는 해결되지 않는다.

대상이 지원하면 벡터 SVG를 보존한다. PNG는 기본적으로 벡터/HTML에서 **의도한 표시 폭·높이의 2배**로 렌더한다. 예를 들어 1200×800 표시에는 2400×1600 PNG를 사용한다. 삽입·표시 폭을 명시하고 `assemble.py`에서는 그림의 `display_width`를 지정해 고해상도 픽셀 때문에 배치 크기가 두 배가 되지 않게 한다. 작은 비트맵을 늘려 만들지 않는다. export 배율은 픽셀 밀도를 높일 뿐 의도한 시각적 굵기를 바꾸지 않는다.

최종 삽입 화면의 실제 크기와 export 픽셀을 확인한다. viewBox·레이아웃 크기, 표시 크기, 래스터 크기, export 배율을 기록한다. 원본 선이 얇은 문제·과도한 축소·부족한 픽셀 밀도·업로드나 뷰어의 재축소를 구분한 뒤 수정한다. 좁은 화면에서 글자와 선을 읽기 어렵다면 구조 전체를 썸네일로 줄이지 말고 단순화·분리하거나 영역 내 스크롤을 제공한다. 사용자의 원본 이미지를 확인하지 않고 해상도 문제였다고 단정하지 않는다.

## 글꼴과 export

한국어·영어 여부가 아니라 텍스트의 용도로 글꼴을 구분한다.

- **설명용 글자:** 제목·설명·일반적인 구성요소 이름·연결선 설명·범례·캡션은 두 언어 모두 **Noto Sans KR**을 쓴다. 위계는 굵기와 크기로 표현한다(일반 400, 강조 700). HTML/SVG에는 `font-family: "Noto Sans KR", sans-serif`를, plotting 도구에는 같은 실제 글꼴을 설정한다.
- **코드와 정확한 기술 표기:** 코드 블록·인라인 코드·변수명·함수명·타입명·명령어·경로·리터럴 값에는 일관된, 사용 가능한 **고정폭 글꼴(monospace)**을 쓴다. 프로젝트나 제작자의 적절한 코드용 폰트가 있으면 유지하고, 없으면 테마 질문 없이 사용 가능한 고정폭 글꼴을 골라 명세에 기록한다. 이를 Noto Sans KR로 바꾸거나 테마 위반으로 지적하지 않는다.
- **혼합 라벨:** 정확한 기술 표기 부분에만 고정폭 글꼴을 쓰고 주변 설명은 Noto Sans KR로 유지한다. 예를 들어 “Worker pool”은 일반 구성요소 라벨이고 `worker_pool.acquire()`는 코드다. 코드 철자를 보존하고 한글 주석이 있으면 해당 글리프 지원도 확인한다.

대체 글꼴 목록은 표시 실패에 대비한 것이며 의도한 폰트가 렌더되었다는 증거가 아니다.

라벨 측정·배치·export 전에 설명용·코드용 폰트를 모두 로드한다. 각 텍스트 구간에 실제 적용되는 폰트·굵기로 측정하고 줄을 나눈다. CSS 선언만 보지 말고 실제 렌더된 폰트와 한글·라틴 글리프를 확인한다. 이식 가능한 SVG/HTML은 출력 형식과 라이선스가 허용하는 방식으로 폰트를 포함하거나 동봉한다. 글자를 경로로 바꿀 때도 편집 가능한 텍스트 원본을 보존한다. PNG는 래스터화 전에 폰트를 확인한다. 폰트 로드·포함이 실패하면 한계를 밝히고, 폰트 검증 통과를 주장하거나 설명용·코드용 폰트의 역할을 조용히 바꾸지 않는다.
