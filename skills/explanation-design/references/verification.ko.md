# 검증과 개선

검증 도구가 측정하는 범위를 넘어 성공을 주장하지 않는다.

| 층 | 확인 | 증거 |
|---|---|---|
| 구조 | frontmatter·reference·JSON·asset·링크·export 파일 | 실행 명령·exit/result |
| 근거·의미 | 주장과 출처, 인과·실행·제약·실패, 본문/표/그림 일치 | 읽은 위치·계산·실행 시나리오·수정 내역 |
| 시각 | 실제 render의 잘림·겹침·폰트·방향·축·가독성·좁은 화면 | 실제로 본 PNG/HTML·viewport·발견한 결함 |

## 품질 질문

- 첫 문단이 핵심 질문에 답하는가? 독자가 결론과 한계를 다시 설명할 수 있는가?
- 중요한 주장에 재확인 가능한 근거가 있는가? 사실·추론·제안·미확인이 섞이지 않았는가?
- 입력 → 처리 → 상태 변화 → 결과 사이에 비약이 없는가?
- 결과를 바꿀 제약·실패·반례를 빠뜨리지 않았는가?
- 선택한 표현이 이해를 늘리는가? 짧은 질문에 과잉 제작하지 않았는가?
- 그림의 edge·순서·단위·범위가 본문과 같은가? 생략이 보장을 왜곡하지 않는가?

## 전체 제작에 앞서 의미를 점검한다

그림 묶음은 대표 구조도 하나와, 필요하면 흐름·실패 그림 하나를 먼저 제작해 확인한 뒤 같은 시각적 어휘를 전체에 적용한다. 이미 알려진 사용자 선호를 따른다. 이는 검증 단계이지 새로운 승인 절차가 아니다. 마지막에는 납품할 전체 그림에서 이름·기호·크기와 대표 그림에서 발견한 결함 유형을 점검한다.

결론에 영향을 주는 그림마다 구체적 예시를 추적한다. 라벨뿐 아니라 배치가 암시하는 주장도 확인한다. 화살표는 없는 순서를, 나란한 두 경로는 배타적인 연결을, 포함은 없는 소유권을, 막대는 실제로 겹치는 한도가 별도 몫이라는 해석을 만들 수 있다. 소유권은 runtime 인자와 인스턴스 식별자까지 추적한다. 공용 helper 호출이나 식별자 등장 횟수만으로 서로 다른 프로세스가 같은 객체를 쓴다고 단정하지 않는다. “항상·유일·전부”의 범위를 확인한다. 설계 이유가 그럴듯해도 뒷받침하는 근거가 없으면 추론이다.

실제 표시 크기에서 읽는 순서·선 끝점·교차·잘린 라벨·용도별 폰트(명시적 변경이 없으면 설명은 Noto Sans KR, 코드·정확한 식별자는 고정폭 글꼴)의 실제 렌더링과 글리프·선택된 역할 팔레트·대비를 확인하고, 다른 렌더러로 만든 그림끼리 글자 크기도 비교한다. 기하 검사는 결함을 잡을 수 있지만 그림이 의도한 뜻을 전달한다는 증거는 아니다. 깨진 그림을 통과시키려고 검사를 약화하지 않는다. 오탐의 원인과 실제 렌더를 각각 확인한다.

## 독립 다이어그램 평가

그림 묶음, 배치가 소유권·동시성·실패 보장을 전달하는 복잡한 그림, 사용자가 명시적으로 평가를 요청한 경우에는 별도 평가자를 사용한다. 단순한 그림은 작성자 검토로 충분하다. 전체 제작 전 대표 그림을 평가하고, 이후 납품할 묶음의 그림 간 일관성을 확인한다. 내부 검증이며 사용자 승인 단계가 아니다.

위임이 허용될 때 사용 가능한 agent 기능으로 새 문맥의 평가자를 실행한다. 제작자의 대화·추론·자기평가·이전 지적을 상속하지 않는다. 제작자는 평가를 조율하고 원본을 수정하며, 평가자는 수정·게시·추가 agent 생성 없이 관찰과 보고만 한다. 위임이 금지되거나 위임·이미지 열람이 불가능하면 가능한 작성자 검토를 수행하고 독립·시각 평가 불가를 명시한다. 통과로 처리하지 않는다.

1. **그림을 먼저 읽는다.** 실제 렌더 이미지, 의도한 표시 크기, 독자의 질문·대상, 독자가 실제로 보게 될 캡션·주변 문맥만 전달한다. 평가자는 이미지를 열어야 하며 SVG/HTML 소스 읽기로 대체하지 않는다. 질문에 해당하는 경계·소유권·순서·동일성·실패 결과를 어떻게 읽었는지와 모호한 부분을 기록한다. 제작 명세·원본 근거·예상 답은 아직 공개하지 않는다. 첫 해석을 회수해 보존한 뒤 다음 자료를 전달한다.
2. **근거와 대조한다.** 첫 해석을 받은 뒤 같은 평가자에게 필요한 명세 발췌, 선택된 테마와 사용자의 명시적 변경, 버전이 있는 최소 원본 근거, 확보한 기하·폰트·export 관측을 전달한다. 작성자의 자기평가와 benchmark 정답지는 제외한다. 처음 읽은 의미를 근거와 대조하고 필요한 이미지를 다시 확인한다. 제공되지 않은 계약은 미확인으로 남긴다. 표현 유형·도형 선택·추상화 경계·역할 색과 강조·개요와 상세 대응·실제 크기의 가독성을 확인한다. 해당 산출물에 적용되는 명세와 명시적 변경을 기준으로 스타일을 판단한다. 색상 불일치를 지적하기 전에 역할 식별·상태·독자의 주의를 끄는 강조를 구분한다. 코드용 폰트를 설명용 폰트 위반으로 지적하지 않으며 혼합 라벨은 용도별로 확인한다. 이미지만 보고 정확한 폰트를 확정하지 않는다. 실제 렌더 폰트 관측을 사용하거나 해당 검사를 미검증으로 남긴다.
3. **수정 가능한 지적을 반환한다.** 각 지적에 `ID | 산출물·버전과 그림 내 위치 | 분류 | 독자가 읽게 되는 의미 | 뒷받침하는 근거 또는 부족한 근거 | 영향 | 최소 수정`을 포함한다. 분류는 의미 오류·가독성 결함·요구사항 불일치·미검증 주장·선택적 취향이다. 의미 오류·핵심 내용의 판독 불가·명시적 요구사항 미충족은 통과를 막지만 취향 차이는 그렇지 않다. 근거가 부족하면 해당 검사는 미검증으로 남긴다. 확인한 산출물·도구 관측·미검증 범위는 별도로 적는다. 미적 총점으로 지적을 대체하거나 개수를 채우려고 문제를 만들지 않는다.
4. **판단하고 재확인한다.** 제작자는 근거 있는 지적을 수용하고, 반박하는 지적에는 근거를 남기며, 미해결은 명시한다. 수정 원본을 고쳐 다시 생성한 뒤 새 렌더와 지적 처리 결과를 평가자에게 전달한다. 수정 효과·새 결함·영향받는 관련 그림을 재확인한다. 후속 평가는 처음 보는 독립 해석이 아니다. 최초 평가 이후 수정·재평가는 최대 두 차례로 제한하며 통과를 막는 문제가 해결되면 일찍 종료한다. 한도에 도달하면 미해결 문제를 보고하고 통과로 표시하지 않는다. 계속 다듬거나 다른 평가자를 새로 불러 한도를 우회하지 않는다. 오해를 일으킨다고 확인된 그림을 검증 완료로 게시하지 않는다.

첫 해석, 근거 전달, 지적과 처리 결과, 평가한 산출물 버전, 반복 횟수, 남은 한계를 작업의 검증 기록에 보존한다. 기계 검사·독립 평가·실제 독자의 이해도는 구분한다. 시험 적용에서는 작성자의 기존 검토 외에 수용된 결함, 기각한 지적, 평가 비용, 새로 생긴 오류를 관측한 범위에서 기록한다. 평가자의 동의만으로 개선을 주장하지 않는다. 평가 과정에서 테마·프로필 저장 질문이나 일상적인 승인 대기를 추가하지 않는다.

## 수정이 최종 산출물까지 이어지는지 확인한다

주장이나 용어를 바꾸면 본문·표 → 그림 수정 원본이나 생성기 → SVG·PNG·export → 문서 참조 → 해당 시 게시된 파일·화면까지 따라간다. 원본을 고쳐 산출물을 다시 만든다. 다음 생성 때 되돌아갈 생성 파일만 수작업으로 고치지 않는다. 영향을 받는 모든 표현에서 폐기한 주장을 찾아보고, 바꾼 말은 문맥으로 확인한다. 모호한 낱말 하나가 서로 다른 개념을 가리켰을 수 있다.

낡은 산출물이 남을 위험이 있으면 해시나 재생성 비교를 사용한다. 이는 파일 일치 검증이며 사실 여부나 화면 표시 검증은 아니다. 업로드 성공·HTTP 200·이미지 참조 개수만으로 독자가 그림을 볼 수 있다고 단정하지 않는다. 실제 파일 형식과 이미지 해석 가능 여부를 확인하고, 접근할 수 있으면 게시 화면을 연다. 원본과 렌더의 일치, 업로드 바이트 일치, 사용자 화면 표시는 각각 구분해 보고한다. 이후 개정을 위해 수정 원본과 첨부 파일의 대응을 보존한다.

## 실행과 수정 기록

깊이 있는 설명은 독자의 목표로 돌아가 조건 하나를 조금 바꿔 확인한다. 다른 가정은 유지하고, 실패 시점을 공개 경계 전후로 옮기거나 공용 helper에 전달하는 인스턴스 ID를 바꾸거나 자원 한도는 두고 사용량을 바꾼다. 설명에서 결과를 도출한 뒤 출처와 대조한다. 필요한 경우 결과가 그대로이거나 알 수 없게 되는 사례도 포함한다. 답하려면 설명에 없는 규칙이 필요할 경우 정답지에만 그 규칙을 추가하지 말고 설명을 보완한다. 요청 크기에 맞춰 수행하며 짧은 답변마다 사용자에게 퀴즈를 내지 않는다.

바꾼 조건·예상 결과 또는 미확인·근거·수정 사항을 기록한다. 작성자의 자체 검토, 독립 agent의 과제 수행, 실제 독자의 이해도는 서로 다른 증거이므로 바꿔 보고하지 않는다. 독립 과제 수행 시험에서는 실행자 prompt에 정답지와 사례별 채점 기준을 넣지 않는다. 다이어그램 평가자는 위 두 번째 단계에서 명시된 요구사항을 받되 benchmark 정답은 받지 않는다.

현실적인 입력을 실제로 풀고 결과를 평가한다. 정답 문구를 regex로 맞추는 것은 행동 평가가 아니다. 코드·설계·데이터처럼 성격이 다른 요청에서 확인한다. 발견한 문제는 원인과 수정을 기록한 뒤 해당 사례를 재확인한다. 다른 사례에도 유효한 일반화인지 확인하고 예제 특화 규칙의 누적을 피한다.

시각 결과를 열어보지 않았다면 “시각 미검증”. browser/export 도구가 없으면 가능한 구조·의미 검증을 완료하고 실제 한계를 명시한다. syntax 통과만으로 설명 품질·시각 품질을 통과 처리하지 않는다. 독립 평가를 수행했으면 평가 입력·자율성·범위와 실제 산출물을 보존한다.
